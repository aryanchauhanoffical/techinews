## Project name
TechiNews

## Elevator pitch (max 200 characters)
Tech news that tells you why to care in one line. It reads a repo's README and shows "Free, open-source ElevenLabs alternative" instead of a description nobody understands.

## Inspiration
I open GitHub Trending every day and close it again, because the descriptions are written by maintainers for maintainers. "82M parameter open-weight TTS model" tells me nothing. A friend would say "it's a free ElevenLabs". That sentence is the difference between scrolling past and tapping.

I wanted a news app where every card has that sentence. Then I noticed the same problem in push notifications: news apps send headlines, while Zepto and Swiggy send a payoff, and theirs get opened. So I applied the same idea there.

## What it does
TechiNews is a mobile reader for developers, founders, and investors.

- **Collects** from 70+ sources several times a day: 31 RSS feeds, 12 YouTube channels, 14 Bluesky accounts, Hacker News, arXiv, Hugging Face, GitHub, Reddit.
- **Ranks and clusters** so one story covered by six outlets appears once, with the best source leading.
- **Writes a hook for every trending repo** by reading its README. Cards lead with "Build AI shopping agents with Claude" rather than the raw description, and show a "Free alternative to X" tag when the repo replaces a paid product.
- **Summarises** the top stories into a lede, key points, and "why it matters".
- **Sends pushes written like a friend texting**: a short payoff-first title and one sentence, with a rule that the story must deliver what the push promises.

Reading is free. **TechiNews Pro** adds instant alerts, topic alerts, and unlimited saves.

## How we built it
- **App:** Flutter, Riverpod, go_router. A pop-art editorial design system with a per-topic colour palette, built from my own mockups.
- **Backend:** FastAPI with MongoDB Atlas. Article documents are the single source of truth; trends and repo shelves are derived queries.
- **Pipeline:** GitHub Actions runs the collector. It collects, ranks with a deterministic scorer, clusters across sources, then sends only the top 30 items per run to Gemini. That cap is what keeps the whole system on free tiers.
- **AI:** Gemini for summaries, repo hooks, and push copy. Cloudflare Workers AI (FLUX) for fallback cover images, stored in Supabase.
- **Auth and push:** Firebase Auth with Google sign-in, Firebase Cloud Messaging.
- **Hosting:** Render free tier for the API.
- **Total running cost: $0 a month.**

## How we used RevenueCat
- **One entitlement, `pro`**, checked at every gate: the ten-save cap, instant alerts, topic alerts, and following a source.
- **Offerings fetched at runtime.** Prices and packages come from RevenueCat, so I can change pricing without shipping an app update. The paywall only shows trial wording if RevenueCat reports an introductory price, so it never promises something that isn't configured.
- **`Purchases.logIn` on sign-in**, so Pro follows the account across devices and reinstalls, with restore purchases on the paywall.
- **Catalog created through the REST API v2**: entitlement, two products ($3.99 monthly, $29 annual), and the default offering.
- **Build-mode key selection.** The SDK deliberately stops a non-debuggable build that carries a Test Store key. I hit that on my own phone, understood why it exists, and made release builds read a separate store key so a test key can never ship.
- **The pricing logic:** the free tier has to be good enough to form a habit, and the paid tier sells time. A digest tells you tomorrow. Pro tells you now, and only about what you named.

As a Next Gen entry there is no store listing, so the demo runs against the **RevenueCat Test Store** and purchases are simulated by the SDK.

## Challenges we ran into
- **GitHub's scheduler is not a clock.** I scheduled the collector hourly and a keep-alive every ten minutes. When I measured, the keep-alive ran at a median gap of 201 minutes and the collector about six times a day. My daily digest was keyed to one exact hour, and in 65 runs none ever started in that hour, so the digest had never been sent. I redesigned so nothing depends on exact timing: the digest goes out on the first run inside a daily window, de-duplicated per day.
- **Free-tier cold starts.** Render sleeps when idle and takes about 32 seconds to wake. My app timed out at 30, which turned "slow" into "broken". Fixed with longer timeouts, one automatic retry, and an external uptime monitor.
- **Android 16 signing.** A keystore generated by JDK 25 could not be read by Gradle's JDK 21, and Google sign-in fails until the release key's fingerprint is registered with Firebase.
- **Reddit blocks datacentre traffic** on its JSON and RSS endpoints, so those pages are read through a rendering service.
- **LLM hooks can be confidently wrong.** One repo got tagged "Free alternative to Clay Millennium Prize Problems". I tightened the prompt to real paid products and added a code-level guard.

## Accomplishments that we're proud of
- A living data pipeline, 2,200+ stories, on $0 a month.
- Hooks that genuinely change whether you tap. "Make AI-generated 3D holographic cards" beats the description it replaced.
- Finding my own bugs by measuring instead of assuming, and writing them down honestly in the README.

## What we learned
- Measure the scheduler before you design around it.
- An LLM is most valuable on the smallest surface: one line on a card did more than a page of summary.
- A paywall is a product decision, not a screen. Deciding what stays free took longer than building the gate.
